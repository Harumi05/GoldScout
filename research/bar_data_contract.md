# Causal M5/D1 materialization — schema v1

This phase is research infrastructure only. It does not import from, modify, or feed the live EA. The source is the **persisted closed M1** JSONL produced by the adopted historical replay; the 132,193,488-tick CSV is not reopened. Versioned code is [`build_causal_m5_d1.py`](build_causal_m5_d1.py) and [`broker_clock_analysis.py`](broker_clock_analysis.py). Large outputs are ignored by Git under `research/output/causal_bars/`.

## Broker clock evidence

The historical timestamp format is `epoch_ms_mt5_server_wall_time`: integer milliseconds encode the MT5 server's wall-clock calendar, **not a proven UTC instant**. The available M1 gaps, observable pauses and runtime calls to `TimeTradeServer()`/`TimeGMT()` do not include an independent same-instant UTC pair or a verified rollover specification. The current result is `broker_clock_status=UNKNOWN`, `broker_server_utc_offset=null`, `broker_day_rollover=null`, `dst_behavior=UNKNOWN`, `confidence=0.0`; session attribution remains false. No PC timezone is used. Optional independently captured same-instant MT5 server/UTC pairs may establish `PARTIAL` offset evidence; they cannot alone establish rollover or DST policy. `VERIFIED` requires separate rollover evidence and a DST policy. Do not relabel technical D1 buckets as market sessions/overnight without that evidence.

Run `python -m research.broker_clock_analysis` to create ignored `research/output/broker_clock_analysis.json`. The paired-samples option accepts JSONL with `capture_id`, `source=MT5_SAME_INSTANT_SERVER_UTC_CAPTURE`, naive `server_wall_time`, and timezone-aware `utc_time`; do **not** substitute PC-local time.

## Bar contract

Run `python -m research.build_causal_m5_d1`. Each materialized bar contains `schema_version=1`, `builder_version=causal-m5-d1-v1`, `source_manifest_id`, `generated_at`, deterministic `bar_id`, `source`, `symbol`, `timeframe`, `timestamp_unit`, `start`, `end`, `available_at`, OHLC, `tick_count`, `avg_spread`, `min_spread`, `max_spread`, `observed_minutes`, `expected_minutes`, `coverage`, `complete`, and provenance with **all source M1 bar IDs**. M5 is aligned to five server-wall minutes. D1 requires an explicit `broker_day_boundary`; while the clock is unverified it uses `00:00` only as a `TECHNICAL_DATE_BUCKET`, with `rollover_status=d1_session_status=UNVERIFIED` and no session/overnight label. A later closed M1 establishes that the previous bucket ended, so `available_at` is conservatively no earlier than that later M1's availability. The final bucket is withheld. Missing minutes remain missing; no forward-fill or synthetic bars. `complete` only means all 5/1,440 calendar minutes were observed, not that a normal broker pause is corrupt.

`causal_bars_index.json` stores counts, coverage percentiles, missing-minute distribution, technical Sunday count, source-gap distribution, output hashes and the clock policy. Existing files with the same schema/source/boundary and matching hashes are skipped; incompatible, partial or altered files abort without silent overwrite. A crash between file publication and index publication leaves a visible partial state requiring manual reconciliation. The raw M1 file's recorded byte size and source fingerprint are checked against the adopted input manifest; this is **not** a new cryptographic hash of the large CSV or proof that the persisted M1 file's unchanged bytes have been independently audited.

## MT5 reference comparison

No independently exported MT5 M5/D1 reference is bundled with the repository or the adopted replay outputs. The default validation report is therefore `NO_MT5_REFERENCE`, not a match. If available, pass `--mt5-m5-reference` and/or `--mt5-d1-reference` pointing to small JSONL exports with server-wall `start` and OHLC. The comparator reports matches, deltas and missing timestamps; it never changes bars to force equality. Its technical samples include complete, incomplete, low quote-activity and Sunday buckets when present. A true London/NY session transition cannot be labeled while the broker clock is UNKNOWN; holiday/pause causes also remain unproven. A differing MT5 D1 rollover should show as missing timestamps, not be normalized away. Mid OHLC from replay may also differ from broker BID/ASK OHLC; report the price convention before interpreting deltas.

## Regime-ready, not a regime engine

The versioned bar identity, causal `available_at`, OHLC, spreads, quote activity, coverage and provenance are intended to support later ATR percentile, realized volatility, ADX, EMA slopes, directional efficiency, range compression, structure, spread regime and tick-activity features on M5/H1/H4/D1. None of these features or `GoldRegimeState` is computed here. Existing H1/H4 replay bars must acquire an as-of availability wrapper before a cross-timeframe decision can use them. Every future feature must satisfy `available_at <= decision_time`; no future pivot, open bar, outcome or market-session label may leak into the decision.
